# План доработок проекта VP_merge

## Краткий вывод по текущему состоянию

Проект находится в рабочем hybrid-состоянии между legacy Widgets и новым QML-интерфейсом.

- Базовая логика загрузки проекта уже вынесена из [`MainWindow`](mainwindow.h)
- Реализован backend facade через [`ProjectFacade`](backend/projectfacade.h) и [`AppController`](appcontroller.h)
- Новый интерфейс на [`qml/main.qml`](qml/main.qml) уже умеет:
  - загружать XML
  - импортировать список XML
  - редактировать проектные параметры
  - редактировать данные штампа
  - подготавливать пути генерации
  - запускать генерацию `PE` / `SP` / `VP` / `GVP`
  - показывать preview-метаданные по документам
- Генераторы `PE` / `SP` / `VP` / `GVP` уже вынесены в backend-сервисы
- Добавлен snapshot/headless export слой для будущего preview/PDF pipeline
- При этом значительная часть legacy-логики всё ещё остаётся в [`MainWindow`](mainwindow.cpp), прежде всего реальный page preview, реальный PDF/печать и часть геометрического/render-кода

## Критерии готовности ближайшего этапа

Ближайший этап можно считать завершённым, если:

- реальный preview и PDF используют один и тот же render pipeline
- [`HeadlessDocumentExportService`](backend/headlessdocumentexportservice.h) создаёт фактический PDF, а не только формальный результат
- геометрия страниц больше не хранится исключительно в legacy renderer-классе
- ошибки export/preview возвращаются через backend API, а не через неявное поведение UI
- пользователь может проверить preview/PDF сценарий полностью из [`qml/main.qml`](qml/main.qml)

## Инструкция по проверке текущей версии программы

Ниже приведён практический сценарий проверки уже реализованной функциональности.

### Что должно быть доступно перед запуском

Убедитесь, что рядом с исполняемой программой или в рабочей директории доступны:

- [`boas.xml`](boas.xml) или другой валидный XML проекта
- шаблон [`perechen.xlsx`](perechen.xlsx)
- ресурсы QML из [`resources.qrc`](resources.qrc)

### Сценарий 1. Проверка запуска приложения

1. Запустите приложение
2. Убедитесь, что открывается окно QML из [`qml/main.qml`](qml/main.qml)
3. В окне должны отображаться блоки:
   - загрузка XML
   - параметры проекта
   - данные штампа
   - подготовка генерации
   - статус backend facade
4. Если окно не открылось, это считается критической ошибкой текущей итерации

### Сценарий 2. Проверка загрузки XML

1. В поле пути XML оставьте [`boas.xml`](boas.xml) либо укажите свой корректный XML
2. Нажмите кнопку загрузки проекта
3. Проверьте, что:
   - обновилось текущее значение XML
   - появился код проекта
   - часть полей штампа и проекта заполнилась автоматически
   - в блоке статуса появилось сообщение об успешной загрузке
4. Если вместо этого появляется сообщение об ошибке, проверьте корректность XML и путь к файлу

### Сценарий 3. Проверка редактирования параметров проекта

1. После загрузки XML измените:
   - децимальный номер
   - наименование проекта
2. Завершите редактирование полей
3. Проверьте, что новые значения остаются в форме
4. Это означает, что данные уже живут в [`ProjectFacade`](backend/projectfacade.h), а не только в UI

### Сценарий 4. Проверка редактирования штампа

1. Измените значения в полях:
   - разработал
   - проверил
   - утвердил
   - нормоконтроль
   - начальник отдела
   - начальник отдела (альтернативное название)
2. После завершения редактирования убедитесь, что значения не сбрасываются
3. Это подтверждает корректную синхронизацию editable state через [`AppController`](appcontroller.h)

### Сценарий 5. Проверка подготовки путей генерации

1. В блоке подготовки генерации:
   - либо оставьте поле базовой директории пустым
   - либо укажите существующую директорию
2. Нажмите кнопку подготовки каталога и путей документов
3. Проверьте, что:
   - появилось значение базовой директории
   - появилось значение каталога `Документация`
   - отобразились пути для ПЭ, СП и ВП
4. В файловой системе должен появиться каталог `Документация`, если его не было

### Сценарий 6. Проверка генерации ПЭ

1. После успешной подготовки путей нажмите кнопку формирования ПЭ
2. Проверьте, что:
   - в статусе появилось сообщение об успешном формировании ПЭ
   - по пути из поля `Путь ПЭ` появился итоговый `.xlsx`-файл
3. Откройте сгенерированный файл и проверьте:
   - файл открывается без ошибок Excel/LibreOffice
   - заполнен штамп
   - присутствуют строки перечня элементов
   - если строк много, созданы дополнительные листы
   - лист `ЛРИ` присутствует и расположен в конце книги

### Сценарий 7. Проверка корректности содержимого ПЭ

При открытии итогового ПЭ дополнительно проверьте:

1. В первой странице корректно записаны:
   - обозначение проекта
   - наименование проекта
   - разработал
   - проверил
   - нормоконтроль
   - утвердил
   - начальник отдела
2. Для групп элементов строки с типом `ElementGroup` визуально отличаются от обычных строк
3. Если вы меняли поля штампа вручную до генерации, в выходном Excel должны использоваться именно изменённые значения
4. Если указано альтернативное название начальника отдела, оно должно попадать в соответствующую ячейку вместо основного

### Сценарий 8. Проверка обработки ошибок

Проверьте как минимум два негативных сценария:

1. Укажите несуществующий XML и нажмите загрузку
   - ожидается сообщение об ошибке
2. Временно переименуйте [`perechen.xlsx`](perechen.xlsx) и попробуйте сформировать ПЭ
   - ожидается сообщение об ошибке генерации
   - приложение не должно аварийно завершаться

### Минимальный smoke checklist

Текущую итерацию можно считать рабочей, если выполняются все пункты:

- приложение запускается
- [`qml/main.qml`](qml/main.qml) открывается корректно
- XML успешно загружается
- поля проекта и штампа редактируются
- пути генерации формируются
- каталог `Документация` создаётся
- ПЭ формируется без сбоя
- итоговый `.xlsx` открывается и содержит ожидаемые данные
- ошибки отображаются в интерфейсе, а не приводят к падению приложения
